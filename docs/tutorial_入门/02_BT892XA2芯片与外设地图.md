## 1. 内存映射：flash / RAM / SFR 在哪里

### 1.1 三个地址空间

BT892XA2 把整个 4GB 地址空间（**32 位地址**）划成几大块。**从编译器视角**，你只需要关心 3 个：

```
        ┌─────────────────────────────────┐ 0xFFFF_FFFF
        │         外设 / SFR 区             │
        │       (SFR0、SFR1、SFR3…)         │
        ├─────────────────────────────────┤ 0x0010_0000
        │           保留                   │
        ├─────────────────────────────────┤ 0x0001_0000
        │           保留                   │
        ├─────────────────────────────────┤ 0x0001_0000  ← RAM 起始
        │          RAM (~32 KB)            │
        │     .bss + .data + 栈 + 堆        │
        ├─────────────────────────────────┤ 0x0000_0000
        │       Boot ROM (固定 2 KB)        │
        └─────────────────────────────────┘ 0x0000_0000
                ↑ 注意 flash 在另外地址空间
```

> flash 和 RAM 是**两个独立地址空间**，并不像 x86 那样共享；CPU 用**专用指令**（`l.eb`(load) / `s.eb`(store)）访问 SFR，把数据从 flash 拷到 RAM 的启动代码在 SDK 里实现。

### 1.2 flash 在哪

flash（程序存放处、只读运行）在另一个地址空间，链接脚本 `ram.ld` 里描述成：

```
app/projects/standard/ram.ld  ←  别看名字叫 "ram"，是链接脚本
```

打开它，能看到类似：

```
MEMORY {
    rom (rx)  : ORIGIN = 0x00000000, LENGTH = 384K   /* flash */
    ram (rwx) : ORIGIN = 0x00100000, LENGTH = 32K    /* 实际 RAM */
}
```

**关键事实**：

| 段 | 内存类型 | 大约 | 谁在用 |
|---|---|---|---|
| `.text` | flash | 含 SDK + 你的代码 | 所有函数体 |
| `.rodata` | flash | 含字符串常量 | `printf("hello")` 里的 `"hello"` |
| `.data` | RAM（启动时从 flash 拷过来）| 已初始化全局 | `int g = 1;` |
| `.bss` | RAM（启动时清零）| 未初始化全局 | `int g;` |
| **总计 RAM** | RAM | ~32 KB | + 栈 + 堆（堆通常没用） |

### 1.3 13 KB BSS 限制（重要）

> 这是新手最常忽略的问题——**BSS 有限**，大了 link 直接报错。

为什么只有 13 KB？SDK 默认链接布局：

```
.bss: 大约 13 KB    (剩余归其他段)
+ 你的 static 数组、play_list、临时缓存
```

如果你加了 `static u8 buffer[4096]` × 几个，**链接器会拒绝**。错误长得像：

```
region 'ram' overflowed by 2560 bytes
```

**实战教训**：
- `wav_test.c` 的 BSS 用了 ~890 B（见 `wav_test.c:119-126`）
- `tf_test/fat_test` 的 BSS 都在 KB 级
- 全部加在一起 ~12 KB，离上限还有余

**避免**：
- 不要在堆栈外开 >1 KB 的 buffer（512 B 够用）
- 想做大 buffer 改用 `__attribute__((section(".aram.xxxxx")))`，放到 RAM 的备用段
- 详见 `tf_test_summary.md §5.1`（TF 实测时的 13 KB vs 6 KB 权衡）

### 1.4 链接脚本的两个角色

`ram.ld` 干两件事：

1. **MAPPING**（刚才看的 `MEMORY` 块）：告诉编译器每个段去哪
2. **SECTIONS**（同文件下半段）：把 .o 文件里的 `.text / .data / .bss / .rodata` 实际安排进内存

> 💡 改 `ram.ld` 是**危险动作**。新手阶段 99% 时候不需要。

## 2. SFR 概念：访问外设的"地址 + volatile"套路

### 2.1 什么是 SFR（Special Function Register）

每个外设（UART / DAC / GPIO / ADC / SDIO…）在 SFR 区**有一块地址**。访问它 = 控制外设。

> 在 x86 你写 `outb(value, 0x3F8)`；在 MCU 上你写 `*((volatile u32 *)0x50000008) = 1;` —— 但 SDK 已经帮你把"地址"换成了"名字"。

### 2.2 `sfr.h`：把地址换成名字

打开 `app/platform/header/sfr.h`（这一类 header 都以 `sfr` 前缀）。

```c
// app/platform/header/sfr.h 片段
#define SFR0_BASE       0x40000000UL
#define SFR1_BASE       0x40010000UL
#define SFR3_BASE       0x40030000UL

/* SFRxx_yy 寄存器宏 —— 偏移 x 按 4 字节(1个 word)对齐 */
#define SFR_RW(addr)    (*((volatile u32 *)(addr)))

#define WDTCON          SFR_RW(SFR0_BASE + 0x0C*4)   /* Watchdog */
#define GPIOADE         SFR_RW(SFR0_BASE + 0x??*4)   /* port A drive-enable */
#define AUBUFDATA       SFR_RW(SFR1_BASE + 0x01*4)   /* DAC, 写到这就 = 给 DAC 喂一个采样 */
// etc.
```

**三个关键写法**：

| 写法 | 含义 |
|---|---|
| `volatile u32 *` | volatile 告诉编译器"这地址在后台可能被改"，不要缓存到寄存器 |
| `*(volatile u32 *)(addr)` | 访问某地址 |
| `SFR_RW(addr)` | 上面的宏包装；`SFR_RO` 只读、`SFR_WO` 只写 |
| `BASE + offset*4` | 4 字节对齐；高位给外设组别、低位给寄存器偏移 |

### 2.3 volatile 不能漏

```c
/* 错误 — 编译器可能优化掉 "因为我没改" */
#define WDTCON  (*((u32 *)0x40000000))

/* 正确 — 标 volatile，强制每次都从内存/外设读 */
#define WDTCON  (*((volatile u32 *)0x40000000))
```

**`volatile` 的两个用途**：

1. **后台 ISR 会改值**：如果你的主循环和 ISR 共用一个变量，不标 `volatile`，编译器**会**优化掉重读（一次性读到寄存器，然后循环里就只读寄存器副本）
2. **访问外设寄存器**：地址 0x40000000 不在 RAM 区，是 SFR 区，编译器不知道有什么后果，每次必须真实读写

**实战 case**（来自 `wav_test.c`）：为什么 `s_paused` 要标 `volatile`：

```c
// app/projects/standard/wav_test/wav_test.c:87-89
static volatile bool s_paused;             /* 主循环读 */
                                        /* ISR 不改，但另一个任务可能改 */
                                        /* 这里是因为 main 和 .bss 优化 */
```

如果是 ISR 写、主循环读，**必须** `volatile`，否则你会看到"按了键毫无反应"。

### 2.4 SFR_RW/RO/WO 选哪个

| 宏 | 可读 | 可写 | 用途 |
|---|---|---|---|
| `SFR_RW(addr)` | ✅ | ✅ | 绝大多数通用寄存器（如 GPIO 方向） |
| `SFR_RO(addr)` | ✅ | ❌ | 只读状态寄存器（如状态位） |
| `SFR_WO(addr)` | ❌ | ✅ | 只写（如 AUBUFDATA —— 你只能 push，没法读最后 push 的）|

`SFR_RO`/`SFR_WO` 是 SDK 给你**防止误操作**的小技巧——比如你写 `value = AUBUFDATA` 编译器会直接报错（不能读只写寄存器）。

### 2.5 普通内存 vs SFR：操作开销

读 RAM：~ 1 个时钟周期，等同于普通变量；
读 SFR：**至少** 2-3 个时钟周期（总线仲裁 + 同步）；
读 flash：**程序计数器** 顺序取指的延迟更复杂。

> 对 100 MHz 的 MCU 而言，这些都是 ~10 ns 级，不用焦虑——但遇到高频循环要知道 SFR 是个"非 RAM"。

## 3. SFR 总线一览（一屏图）

BT892XA2 把 SFR 划分为 **多组总线**，每组有自己的基址 + 范围：

```
SFR 总线分组（节选，不完整）
══════════════════════════════════════════
SFR0 (0x4000_0000) ─┬─ Clock   : SYSCLK / HCLK / PCLK
                    ├─ Timer    : TMR0-5 (含 5ms tick 用到的)
                    ├─ UART     : UART0 (HUART) + UART1
                    ├─ WDT      : WDTCON
                    ├─ RTC      : RTC 时钟 + 闹钟
                    ├─ GPIO     : port A-E
                    ├─ ADC      : SAR ADC 控制器
                    ├─ SDIO     : SD0 / SD1
                    └─ I2C×2    : i2c 主 / i2c 从
                    
SFR1 (0x4001_0000) ─┬─ DAC      : AUBUFDATA / AUBUFCON / DAC_SR
                    ├─ IIS      : 数字音频 I2S 接口
                    ├─ PWM0-3
                    ├─ LCD      : 显示控制器（如果有屏）
                    ├─ USB      : USB-OTG
                    └─ SPDIF

SFR3 (0x4003_0000) ─┬─ USB Phy  : USB 物理层
                    ├─ PLL      : 锁相环
                    ├─ PWR      : 电源管理 / 休眠
                    ├─ LVD      : 低压检测
                    ├─ Charge   : 充电管理
                    └─ Touch    : 触摸控制器（如果有）

(完整列表打开 app/platform/header/sfr.h 查)
```

### 3.1 怎么定位某个 SFR

1. **打开 SDK 中的 `app/platform/header/sfr.h`**（约 7000+ 行宏）
2. Ctrl+F 搜名字（GPIOA / WDTCON / AUBUFDATA / DAC_SR…）
3. 看注释里的 `BASE + offset*4` 这条路径
4. 对照 SDK 数据手册（**数据手册** vs **sfr.h 宏**：数据手册讲位语义，sfr.h 给你写位置）

### 3.2 一屏速查（每组具体寄存器）

| 总线 | 主要 SFR 名字 | 用途 | SDK 文件 |
|---|---|---|---|
| SFR0 / Clock | `SYSCLK / HCLK / PCLK` | 时钟分频 | `api_clock.h` |
| SFR0 / WDT | `WDTCON` | 看门狗 | `macro.h:17-21` 提供 `WDT_CLR/EN/DIS/RST` |
| SFR0 / Timer | `TMR0CNT / TMR0PR / TMR0CON` | 5ms tick 用 | `bsp_sys.c:347` |
| SFR0 / UART | `UT0DATA / UT0CON` | 串口（HUART 默认 PB3） | `bsp_uart.c` |
| SFR0 / GPIO | `GPIOA / GPIOADIR / GPIOADE ...` | port-A/B/C/D/E | `bsp_gpio.c` |
| SFR0 / SDIO | `SDxCMD / SDxARG / SDxCON / SDxCON2` | SD 卡控制 | `bsp_sd.c` |
| SFR0 / ADC | `SARADCCTRL / SARADCDATA` | 10-bit SAR ADC | `api_saradc.h` |
| SFR1 / DAC | `AUBUFDATA / AUBUFCON / DAC_SR` | 音频输出 | `bsp_iis_ext.c` |
| SFR1 / IIS | `IISxDATA / IISxCON` | 数字音频串行 | `bsp_iis_ext.c` |
| SFR1 / PWM | `PWMCON` 系列 | 蜂鸣器 / 喇叭推挽 | `api_pwm.h` |
| SFR3 / PWR | `PWRCON / LP_CON` | 休眠 / 唤醒 | `api_pwr.h` |
| SFR3 / LVD | `LVDCON` | 低压检测 | `bsp_sys.c` |

## 4. GPIO 架构：12 个寄存器数组怎么配

### 4.1 5 个端口

BT892XA2 有 **port-A / B / C / D / E**（有时会看到 F，看具体型号），共 ~50 个 GPIO。

```
GPIOA = PD0-PD7 之类编号   （PA0-PA7 等同于 "pin A0-A7"）
GPIOB = PB0-PB7
...
```

### 4.2 12 个寄存器 per port

每个端口都跟 12 个寄存器关联（SDK 在 `bsp_gpio.c:54-89` 一并封装）：

| 寄存器名 | 1= | 用途 |
|---|---|---|
| `GPIOx` | -- | 当前脚上的电平（只读） |
| `GPIOxSET` | 1 | 写 1 = 把脚拉高（不影响其他 bit） |
| `GPIOxCLR` | 1 | 写 1 = 把脚拉低（不影响其他 bit） |
| `GPIOxDIR` | 0/1 | 0=in, 1=out（**0 是 in，不要写错**）|
| `GPIOxDE` | 0/1 | 0=关闭驱动、1=使能；必须开才能真正影响输出电平 |
| `GPIOxFEN` | 0/1 | 0=关闭翻转、1=使能（输出去耦，智能外设专用） |
| `GPIOxDRV` | 0/1 | 0=小电流、1=大电流（驱动 LED 用 1） |
| `GPIOxPU` | 1 | 上拉 50K 左右（输入用） |
| `GPIOxPD` | 1 | 下拉 50K 左右 |
| `GPIOxPU200K` | 1 | 上拉 200K（极弱上拉，省电） |
| `GPIOxPD200K` | 1 | 下拉 200K |
| `GPIOxPU300` | 1 | 上拉 300 ohm（强电流用） |
| `GPIOxPD300` | 1 | 下拉 300 ohm |

### 4.3 标准"配置普通 GPIO 输出"配方

```c
/* 1. 想用哪一脚：从 io_def.h 找枚举 */
#define IO_PD0    ...    /* port-D 0 */

/* 2. SDK 帮你做的：bsp_gpio_cfg_init */
gpio_t led;
bsp_gpio_cfg_init(&led, IO_PD0);
                ↑ 自动 DIR=1, DE=1, FEN=0, PU/PD=0

/* 3. 设置高 / 低 */
bsp_gpio_set(&led, 1);   // → GPIOxDSET |= BIT(0), 拉高
bsp_gpio_set(&led, 0);   // → GPIOxCLR = BIT(0), 拉低
```

### 4.4 读改写陷阱

> ⚠️ **第一大芯片坑**：用 `|=` 直接改 GPIOx 会丢别的位的状态。

```c
/* 错误 */
GPIOA |= 0x02;       /* 想设 PA1 为高 */
                     /* 但读取 → 改 → 写入  三步之间被 ISR 改了 → 丢值 */

/* 正确 */
GPIOASET = 0x02;     /* SET 寄存器：只动 PA1，其他位不变 */
                     /* 这才是原子写 */
```

这是为什么 SDK 提供 `SET/CLR` 两个独立寄存器。**永远**优先用：

| 改某几位 | 用什么 | 注释 |
|---|---|---|
| 想**置位**某 bit | `GPIOxSET = BIT(n)` | 只动 1 bit |
| 想**清零**某 bit | `GPIOxCLR = BIT(n)` | 只动 1 bit |
| 想**读改写**某 bit | 暂时用不上，**不要**写这种代码 | 总有更优方案 |
| 想**同时改几位** | `GPIOxBSET` / `GPIOxBCLR` （有的芯片有） | |
| 读脚 | `GPIOx & BIT(n)` | 不是 `GPIOxSET & BIT(n)`！ |

### 4.5 `gpio_t` 结构体（高阶抽象）

```c
// app/platform/header/gpio.h
typedef struct {
    volatile u32 *sfr;       /* 指向端口 SFR 基址 */
    u8 num;                  /* pin number 0..15 */
    ...                      /* DE/PU/PD 等 */
} gpio_t;
```

有了 `gpio_t`，你不用记"PD0 在哪个 SFR"，全部交给 `bsp_gpio_set(&g, 1)`。

具体字段：

| 字段 | 含义 | 例子 |
|---|---|---|
| `sfr` | 端口 SFR 基址（GPIOA / GPIOB ...）| `&GPIOA`、`&GPIOB` |
| `num` | pin 编号 0..15 | PD0 的 num=0 |
| `sfr[GPIOxDIR]` | 共享数组，通过偏移索引 12 寄存器 | `[0]`=DIR, `[1]`=DE, `[2]`=FEN... |

[§6 的 blinky](#6-你的第一个上手程序-blinky-on-pd0) 会讲到怎么初始化。

## 5. FUNCMCON0/1/2/3：怎么让一个引脚"既当 GPIO 又当 UART"

### 5.1 问题：复用

**每个 GPIO 都能干 4-8 件事**——比如 PA7 可以是：
- 普通 GPIO
- UART0 TX（HUART 默认）
- SD0 CMD（SD 卡命令线）
- 触摸通道
- …

如果你要让 PA7 当 GPIO 用，**必须**先**关掉**别的功能——这就是 FUNCMCON0/1/2/3 干的事。

### 5.2 FUNCMCON 是什么

4 个 32-bit 寄存器，每 2 bit 控制一个 GPIO 的"功能选择"：

| FUNCMCONx | 含义 |
|---|---|
| `FUNCMCON0` | 端口 A 上每个脚切到哪个外设的寄存器（共 ~16 个脚，占 32 bit） |
| `FUNCMCON1` | 端口 B |
| `FUNCMCON2` | 端口 C |
| `FUNCMCON3` | 端口 D & E |

典型用法（`bsp_iis_ext.c` 里能找）：

```c
/* 把某个 GPIO 还给"通用 GPIO" */
#define SET_GPIO_FUNC(port_bit, idx) do { \
    FUNCMCON##port_bit = (FUNCMCON##port_bit & \
                          ~(3u << (idx * 2))) | \
                         (0u << (idx * 2)); \
} while (0)
```

### 5.3 为什么忘设 FUNCMCON 会"写 GPIO 写不进"

> 🚨 **第二大芯片坑**：默认上电时，**很多 GPIO 是给外设用的**。

你的代码：

```c
GPIOADE |= 0x01;          /* 想让 PD0 输出高 */
GPIOASET = 0x01;
```

什么都没发生——因为 PD0 默认属于 SDIO 的 CLK，**写 GPIOD 的寄存器根本不影响物理脚**。

**检测方法**：
1. 用示波器看物理脚
2. 没动作 → 90% 是 FUNCMCON 没切
3. SDK 会帮你切；例如 `SDx_MUX_IO_INIT()`（见 `bsp_sd.c`）一次切完所有 SD 引脚

**修法**：
- 用 SDK 提供的 `bsp_gpio_cfg_init(&g, IO_PD0)` —— 它**自动**把 PD0 切回普通 GPIO 再配
- 看 `bsp_gpio_cfg_init` 内部调了 `gpio_mux_set(g->num, 0)` 之类

### 5.4 实测案例

`tf_test_summary.md §4.2` 描述过一次踩坑：写 `SDx_MUX_IO_INIT()` 后能通讯，但忘了先关闭 SD 控制器，下次上电 PE5/6/7 还没等到 pwrkey 初始化就先被 SDIO 当成 CMD 线拉低了——结果 pwrkey ADC 读出奇低。

**经验**：
- **每个 IO 项目开始前**先确认它的**默认 FUNCMCON** 值
- 切换使用模式时，先选 FUNCMCON 再初始化外设

## 6. 你的第一个上手程序：blinky on PD0

> 这是"我有板子、工具链通、想立刻做点什么"的标准操作。

### 6.1 准备

- 板子通电
- 用杜邦线把 PD0 接到一个 LED（+ 限流电阻 ~1K 到 GND）
- **同时**把 HUART USB-TTL 接上 PB3（不是 PD0）
- 工具链按 [00_新手上路清单 §1](00_新手上路清单.md) 配好

### 6.2 代码（30 行能跑）

```c
/* examples/blinky_test/blinky_test.c — 让 PD0 上的 LED 闪 */
#include "include.h"

AT(.com_text.blinky)
void blinky_test_run(void)
{
    printf("\n[BLINKY] start\n");

    gpio_t led;
    bsp_gpio_cfg_init(&led, IO_PD0);     /* 自动切到 GPIO + DIR=out + DE=1 */

    int toggle = 0;
    for (;;) {
        bsp_gpio_set(&led, toggle ? 1 : 0);    /* 翻转 */
        toggle = !toggle;
        delay_5ms(100);                    /* 0.5s 一次 */
        WDT_CLR();                         /* 不喂狗 ~ 1-2 秒会重启 */
    }
}
```

### 6.3 接 main.c

打开 `app/projects/standard/main.c`，找函数（在 `// [WAV_TEST]` 那块的下面）：

```c
// 原：wav_test_run();
blinky_test_run();    /* 临时换到 blinky */
```

### 6.4 配置

`bsp_gpio_cfg_init` 在 `app/platform/bsp/bsp_gpio.c`。
确保 SDK 配置允许 PD0 做 GPIO，不被某个外设霸占。  
打开 `config.h`，搜 `IO_PDx_FCFG`（默认应该是 0 = GPIO；如果不是，**先确认**）。

### 6.5 Build + 烧

按 [00 §2](00_新手上路清单.md)（编译一次）+ [00 §4](00_新手上路清单.md)（烧录）。

### 6.6 成功标志

- LED 每 0.5 秒切换明暗（50% duty cycle）
- 串口看到 `[BLINKY] start`（可选，如果你 printf 太多 flash 跑飞，删掉）
- 拔掉 LED 杜邦线也能正常工作

### 6.7 失败 → 翻

| 现象 | 跳 |
|---|---|
| 完全不闪 | [§5.3 FUNCMCON 是不是没切](#53-为什么忘设-funcmcon-会写-gpio-写不进)；用示波器看 PD0 |
| 闪但只一次 | `WDT_CLR()` 漏了，1-2 秒后重启 |
| 没 0.5 s 节奏 | `delay_5ms` 没生效（找 `clib.h:60`），改用 `delay_ms(500)` |
| printf 之后什么都不出 | 可能 linker 把 .com_text 段切错；改回 `.text` |
| 卡死 / 复位 | 不在 .com_text 的部分，跑 main loop 时被 bootloader 复位 |

### 6.8 进阶：换成呼吸灯（用 PWM）

把上面 `bsp_gpio_set` 换成调 `api_pwm_channel_init` 的输出——参见 [§8 PWM](#8-其他外设一览pwmtimeruartspii2c) 提到在哪查。

## 7. SAR ADC：给所有按键共用那一根

### 7.1 为什么 BT892XA2 的按键都"用同一根脚"

> 一颗便宜的 BT892XA2 只有 28-50 个 GPIO，做大喇叭产品时**只有一个 WKO 引脚**（PB5）能进 SAR ADC。结果：所有按键**分压**到这个 ADC，读到不同电压代表不同按键。

详见 [04_按键系统完全指南 §2](../tutorial_入门/04_按键系统完全指南.md)；本节教你**怎么用 ADC 本身**。

### 7.2 通道清单（节选）

| 通道 | 脚 | 用途 |
|---|---|---|
| ADC channel 0-7 | PA0-PA7 | 通用 ADC 输入 |
| ADC channel 8 | PE0 | 一般 GPIO 之外 |
| ... | ... | |
| ADC channel 12 | PB5 (WKO) | **按键用** |
| ADC channel 13-15 | PB6-PB7, PE5 等 | 电池、温度等 |

打开 `app/platform/libs/api_saradc.h` 看完整列表，约 16-20 个通道。

### 7.3 怎么读一次

```c
#include "api_saradc.h"

u16 adc_val;

/* 读 PB5（按 key） 一次 */
saradc_setup_time_set(120);              /* 120 μs 建立时间（见 §10.4） */
adc_val = adc_get_value(ADCCH_PB5);      /* 返回 0..1023 (10-bit) */
printf("PB5 = %u\n", adc_val);
```

> 注：`saradc_setup_time_set` 在本 SDK 是**空宏**（见 `api_saradc.h:10` 的注释 + `§10.4` 我们实测的实坑）

### 7.4 完整示例：读 PB5 一次

```c
/* examples/adc_single/adc_single.c */
#include "include.h"

AT(.com_text.adc_example)
void adc_single_run(void)
{
    printf("\n[ADC] single read of PB5 (WKO), press S5/S6/S7 to read\n");

    /* 别忘了转换 IO 配置：把 PB5 切回 ADC 输入 */
    /* 默认上电时 PB5/ADC0/12 是 WKO 状态 */
    adcch_io_pu10k_enable(ADCCH_PB5);   /* enable 10K pullup —— 让分压电路有基准 */

    /* 校正，SAR ADC 需要一次校准 */
    saradc_calibration();                 /* 在 sdkapi_dac 等库中 */

    for (;;) {
        u16 v = adc_get_value(ADCCH_PB5);
        printf("PB5 = 0x%03X (%4u)\n", v, v);

        delay_5ms(50);     /* 50 ms 一次，肉眼能看清 */
        WDT_CLR();
    }
}
```

### 7.5 解释 SAR ADC 工作机制

- **SAR** = Successive Approximation Register
- **10-bit**：每次转换返回 0..1023
- **分压原理**：Vadc = VDD × (R_ext ÷ (R_ext + R_pullup))

    例：DDKEY 上拉 10K，按键电阻 12K
    Vadc = 3.3V × 12K / (10K + 12K) = ~1.80V
    ADC = (1.80V ÷ 3.3V) × 1024 ≈ ~558 = 0x22E

### 7.6 怎么取值范围

| 输入电压 | ADC 值 |
|---|---|
| 0 V | 0 |
| 3.3 V | 1023 |
| 1.65 V（VCC/2）| 511 |

> ⚠️ **不要直接乘 Vcc**——晶体管之间有 offset、ADC 有非线性，必要时先校准。SDK 默认精度 8-bit 够用。

### 7.7 进阶：批量读多通道

读多通道不要用 `adc_get_value` 调 N 次（每次等结果 ~30 μs），改用 `saradc_scan`：

```c
/* 见 bsp_sys.c 里的 scan 例程 */
saradc_scan_set(SARADC_SCAN_PB5 | SARADC_SCAN_PA0);  /* 同时开 PB5 + PA0 */
u16 vals[2];
saradc_scan_get(vals);        /* 一次拿所有通道 */
```

### 7.8 进阶：电池电压（PE5，channel ?）

PE5 是电池分压脚（在 `tf_test_summary §5.3` 有提）：分压后接 ADC 的某个 channel，读出来换算 Vbat。  
设 Vbat_meas = (ADC_val ÷ 1024) × Vref × (R1 + R2) ÷ R2 即可。

## 8. 其他外设一览（PWM/Timer/UART/SPI/I2C）

### 8.1 总览

每个外设给一段话：一个 SFR 名 + 一个 SDK API 名字 + 一句"何时用"。

| 外设 | SFR 名 | SDK API | 一句说明 |
|---|---|---|---|
| **PWM** | `PWMCON` / `PWMDUT` | `api_pwm.h` PWM_Ch_Init / PWM_SetDuty | 蜂鸣器、LED 呼吸、LEDC、音圈驱动 |
| **TIMER** | `TMR0CNT` / `TMR0PR` | `delay_5ms` 内置 | 5ms tick 是 TMR3；1ms 用 TMR0；time 用 RTC |
| **UART** | `UT0DATA` / `UT0CON` | `bsp_uart.c` printf | 调试串口 / BLE SPP / AT 命令 |
| **SPI** | `SPIxDATA` / `SPIxCON` | `bsp_spi.c` | 跟外部 flash / 屏 / codec 通讯 |
| **I2C** | `I2CxDATA` / `I2CxCON` | `bsp_i2c.c` | 触摸、电容咪、PMIC |
| **SDIO** | `SD0CMD / SD0ARG` | `bsp_sd.c` | 我们的 SD 卡核心（[tf_test_01_02](../tf_test_01_02.md)） |
| **I2S / IIS** | `IISxDATA` | `bsp_iis_ext.c` | 数字音频外扩（外部 DAC 用） |
| **DAC** | `AUBUFDATA / AUBUFCON / DAC_SR` | `api_dac.h` `dac_spr_set / dac_set_dvol` | 内置直接出模拟喇叭 |
| **ADC** | `SARADCDATA` | `api_saradc.h` | 见 [§7](#7-sar-adc给所有按键共用那一根) |
| **RTC** | `RTCCON` / `RTCALRM` | `api_rtc.h` | 闹钟、计时、deep sleep 唤醒 |

### 8.2 怎么选外设

1. **看 SDK 已有功能**（plugin/func_*）：SDK 大概率已经支持了——看到 `func_music.c`、`func_bt.c`、`func_speaker.c` 等；
2. **看 SDK API**：`app/platform/libs/api_*.h`，**28 个** `api_*.h` 速查 [→ Doc 03 §5](03_SDK架构与运行模型.md)；
3. **实在没现成的** → 看 `bsp_*.c / app.s/project/standard/`，照着一份改。

### 8.3 一个具体决定：喇叭直接出 vs I2S 出

**喇叭直接接 DAC**：本项目默认；
**喇叭经 I2S 外置 DAC**：外置 chip 如 ES8388、SGTL5000 时用，质量更好但 BSS 多 ~2 KB。

| 用法 | SDK 接口 |
|---|---|
| 直接 DAC | `AUBUFDATA = u32`（[wav_test_02.md](../wav_test_02.md) §3） |
| I2S 外置 | `iis_config_init + iis_write_fifo` |

## 9. 怎么读数据手册的位域表

### 9.1 一段示例

数据手册里 WDTCON 寄存器：

```
WDTCON  (Watchdog control)
  Bits  [15:8]  RW   reserved, 0 only
  Bits  [6:4]   RW   WTS   - 010=enable, others=disable
  Bits  [3:0]   RW   WTT   - 0xA=clear, write 1 = clear, write 0 = ignore
```

含义：

- **写 0xA 到 bit [3:0]** = 清看门狗（WDT_CLR 必须写 0xA）
- **写 0x110 到 bit [4]** = 启用看门狗（bit 4 = 1）
- SDK 给你 `WDT_CLR/EN/DIS/RST` 宏（`macro.h:17-21`）

### 9.2 实战例：DAC_SR

数据手册：

```
DAC_SR  (DAC Sample rate select)
  Bit   [3]   RW   1 = use SPR_44100 mode
  Bit   [2:0] RW   000=SPR_8000 ... 111=SPR_48000, see table 4-7
```

但 SDK 函数 `dac_spr_set(SPR_44100)` 帮你做了：

```c
// app/platform/libs/api_dac.h:25-42
#define SPR_48000     0
#define SPR_44100     1   ← 你传 1，它就帮你写 1 << 0 | 0 << 3
```

### 9.3 怎么确认自己有没有配错

**验证方法**：
1. 写完后**立刻读**回来，对比
2. 用 SDK 提供的"读回函数"（如果有）
3. 编译时检查 macro.h 的宏定义是不是已经填对

⚠️ 别忘了 : 如果 SDK 帮你封装了**别用 raw 寄存器**。`AUBUFDATA = u32` 比 `*((volatile u32 *)(0x40010004)) = u32` 强 100 倍——前者 `SFR_WO` 宏保证你不会误读，后者没保护。

## 10. 5 个芯片级坑

### 10.1 GPIO 被外设占用 → 写 1 被默默忽略

> 已在 [§5.3](#53-为什么忘设-funcmcon-会写-gpio-写不进) 讲。最常见 4 个原因：
>
> 1. 没设 FUNCMCON
> 2. 设了 FUNCMCON 但忘了使能 DE
> 3. 设了 DE 但 DIR 不是 out
> 4. 设了 DIR=out，但还没初始化 DE

**debug**：用 SDK 的 `gpio_t g; bsp_gpio_cfg_init(&g, IO_PD0);` —— 它会自动帮你做完 1-4 步。

### 10.2 WKO 高阻源 → 0 裕量阈值被防抖吞

> 详尽分析：[wav_test_03.md](../wav_test_03.md) §7.4 + [04_按键系统完全指南 §4](04_按键系统完全指南.md) §4

**症状**：47K 电阻按键按下去**完全不识别**，别的按键正常
**根因**：实测 ADC 值很接近阈值，30 ms 防抖期每轮读数 ±1-2 之间漂移，**永远计不到 6 次稳定**
**修法**：阈值比实测值**至少** 大 18 LSB（实测 0xD3 → 阈值给 0xE5）

### 10.3 DIR=IN 之前读引脚 → 读到上次老值

```c
/* 错误 */
u8 v = GPIOA & BIT(5);   /* 可能返回的是上次的值 */
/* 忘记设 GPIOxDIR = 0 (input) */
```

**debug**：先 `cfg_init(...)`，再读。

### 10.4 漏 `volatile` → ISR 写主循环不响应

> 第 [§2.3](#23-volatile-不能漏) 段。最经典的"我按了键但什么都不响应"原因。

**debug**：所有"在 ISR 里改、主循环读"的全局变量，**统统** `volatile`。

### 10.5 清 WDT 错

`WDT_CLR()` 是个**写特定值 0xA** 的宏（不是清零）：

```c
/* macro.h:17-21 */
#define WDT_CLR()  WDTCON = 0x0A   /* 必须写 0xA */
// 直接 WDTCON = 0; 不会触发清狗！
```

测试代码必须每 100 ms 调一次（详见 [03 §3 WDT 分裂](03_SDK架构与运行模型.md)），否则 1-2 秒后重启。

## 总结：开始之前的核心清单

读完本篇后，**最少要保证**:

- [ ] 知道 RAM 只有 ~32 KB，BSS 上限 ~13 KB（再大就链接失败）
- [ ] 看到 `SFR_RW / SFR_RO / SFR_WO` 三个宏，知道分别能读能写不能写不能读
- [ ] `volatile` 不能漏
- [ ] 改 GPIO 用 SET/CLR 别用 `|=`
- [ ] 每 100 ms 喂一次 WDT（在自定义的测试 main loop 里）
- [ ] 切换 IO 功能前先设 FUNCMCON

如果 6 项均 ✅——你已经可以动手写第一个程序了。**再不确定的：问具体问题 + 带代码片段。**
