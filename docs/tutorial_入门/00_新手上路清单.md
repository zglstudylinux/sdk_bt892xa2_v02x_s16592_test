## 0. 这个清单是什么（不是教程替代品）

## 1. 验证工具链（10 分钟）

### 1.1 打开工程

1. **启动 Code::Blocks**（简称 CB，IDE 全名）
2. **File → Open**：`app/projects/standard/app.cbp`
3. **左下角 Project tab** 应立刻看到 `app` 这个工程名（不是 `hello_world.cbp` 也不是 `wav_test.cbp`）

### 1.2 编译 profile 检查

1. 菜单 **Settings → Compiler**
2. 顶部 **Selected compiler** 选 **`GNU GCC Compiler for RISC-V (riscv32)`**
3. 顶部 **`#defines`** tab：能看到宏 `RV32` 或类似 = 已生效
4. 顶部 **Toolchain executables** tab：
   - **Compiler's installation directory**：应该指向你电脑上的 `riscv32-elf-gcc` 所在目录
   - 看不到？问同事要路径，或重装工具链（见 [快速入门.md](../快速入门.md) §2）

### 1.3 验证成功标志

| 看到 | 状态 |
|---|---|
| CB 标题栏无 `modified` 字样 | ✅ 工程加载完整 |
| Project tab 展开有 `app/projects/standard/` 子项 | ✅ |
| Compiler dialog 顶部有 `riscv32-elf-gcc` | ✅ |
| Compiler dialog 名字带 `RISC-V` 关键字 | ✅ |

| 没看到 | 第一步做什么 |
|---|---|
| Project tab 是空的 | 关 CB 重开；若仍空则工程文件损坏，问同事 |
| `app.cbp` 不在工程列表 | File → Recent projects 找，或重 File → Open |
| 找不到 `riscv32` profile | Settings → Global compiler settings → Selected compiler 下拉找 |

## 2. 编译一次（10 分钟）

### 2.1 触发构建

- **Build → Build**（快捷键 **Ctrl+F9**）
- **下方 Build log** tab 应开始滚动

### 2.2 成功标志

```
=== Build log (片段) ===
...
riscv32-elf-gcc -c ... -march=rv32imacxbs1 ...
...
riscv32-elf-objcopy -O binary ... app.bin
...
riscv32-elf-gcc -nostdlib ... -o app.rv32
...
Output   : bin not embedded into target
```

**关键**：最后一行**没有** `error:` 字样。如果有 → 见 [06_踩坑大全.md §1 工具链 8 坑](06_踩坑大全.md)

### 2.3 检查产物文件

转到 File Manager（资源管理器），打开：

```
app/projects/standard/Output/bin/
```

应该看到这些文件（按修改时间都是**刚才构建**的时间戳）：

| 文件 | 大约大小 | 用途 |
|---|---|---|
| `app.bin` | ~700 KB | 原始二进制镜像 |
| `app.dcf` | ~720 KB | **真正要烧录的文件** — BT892XA2 自有容器格式 |
| `app.rv32` | ~900 KB | ELF 格式，给 objdump/map 工具用 |
| `map.txt` | ~200 KB | 链接器输出的函数/段分布（调试灵魂） |
| `xcfg.bin` | ~256 B | 运行时配置（按键表、音频参数等） |

> 💡 **wav_test 默认不开**：上面这些都来自 `main.c → wav_test_run`（Phase 5 默认入口）。要看 `xcfg.bin` 用任何 hex 编辑器，前 16 字节是 reserved header。

### 2.4 失败排查

| 现象 | 跳到 |
|---|---|
| `riscv32-elf-gcc: not found` | [06_踩坑大全 §1](06_踩坑大全.md)；一般是 PATH 错或 profile 没生效 |
| `postbuild.bat error` | 看 Build log 末行；一般是 `xmaker.exe` 退出码非零（参 [01 §9](../快速入门.md) 或 [01 §4](01_工具链与构建产物.md)） |
| 卡在某步无输出 | Ctrl+C 取消；proj 菜单 Reset 一次；再编译 |

## 3. 识别板子（5 分钟）

### 3.1 板子类型

我们的标准教学板叫 **Boombox**，特征：

- **CPU**：BT892XA2（**RISC-V 32-bit + 内置蓝牙**，中科蓝讯 Bluetrum）
- **3 个按键** 通过 PB5（WKO）分压输入：
  - S5 = P/P（0Ω 直通 GND）
  - S6 = PREV（12K 下拉到 GND）
  - S7 = NEXT（47K 下拉到 GND）
- **SD 卡槽** PE5/6/7 三根线复用 SDIO 信号
- **喇叭** 直出 DAC

### 3.2 SD 卡要求

> ⚠️ **必须 FAT32**，不是 exFAT，不是 NTFS。

1. **Windows**：插卡 → 此电脑右键 → 格式化 → 文件系统选 **FAT32** → 分配单元大小 **4096**（推荐）
2. **Mac**：磁盘工具 → 抹掉 → MS-DOS (FAT) → 选 **Master Boot Record / 4096 字节**
3. **Linux**：`mkfs.fat -F 32 /dev/sdX1`

### 3.3 复制测试音乐

把 **`MUSIC.WAV`**（任意 16-bit 立体声 44.1 kHz PCM）拷到 SD 卡**根目录**（不要放文件夹里）。文件名**用 8.3 短名**：`PLAY.WAV`、`SONG01.WAV` 都行，**不能**用 `My Song.wav` 之类长名（Petit FatFs 不支持 LFN）。

> 想听多首？复制几个不同的 `.WAV` 到根，wav_test 会自动枚举成播放列表。

### 3.4 成功标志

| 检查 | 通过 |
|---|---|
| 卡格式 | 文件系统显示 FAT32 |
| 卡根目录 | 看到 `MUSIC.WAV` (或你拷的文件) |
| 卡根目录 | **没有** `System Volume Information/` 之类长名（如果从 Windows 拷来会有，这是 OK 的，但 LFN 不会被枚举） |

## 4. 烧录 .dcf（15 分钟）

### 4.1 工具 + 连接

| 你需要 | 来源 |
|---|---|
| **Downloader.exe** | SDK 工具目录或同事给（公司内部工具） |
| **USB 转串口** | 一根 USB-TTL 线（接 HUART 的 TX+RX+地） |
| **BOOT 引脚触发** | 参考板子原理图（通常是按住 BOOT 键 + 重新上电，或拉某个 GPIO 到特定电平） |
| **HUART 配置** | **PB3**（默认），**115200 8N1** |

> Downloader / BOOT 模式启动的具体动作见 [01_工具链与构建产物 §6](01_工具链与构建产物.md)，下面只讲**参数**。

### 4.2 烧录步骤

1. **断开串口**（如果你现在插着）
2. **按下 BOOT 键**（或拉特定 GPIO）→ 重新上电 / 按 RESET → 板子进入 **download mode**
3. **打开 Downloader.exe** → File → Open → 选 `app/projects/standard/Output/bin/app.dcf`
4. 配置 COM 端口（设备管理器里看 USB-TTL 是 COM?）
5. 点 **Download** 按钮
6. **观察进度条** —— 应在 20-30 秒内从 0% 到 100%
7. 完成后**拔出 BOOT 短路**（如果有）+ 按 RESET 重启板子
8. **重新接上 HUART USB-TTL**（TX ↔ RX 交叉、GND 共）

### 4.3 成功标志

打开任一串口工具（XCOM / Putty / Tera Term / `minicom`），设置 PB3 + 115200 8N1 + 无硬件流控，按**板子 RESET**：

```
=========================================
  [WAV] BT892XA2 WAV Player Test
  [WAV] SDK V02.00
  [WAV] SDIO mode, SD0MAP_G3 (PE5/6/7)
  [WAV] Phase 5 Part 3: playlist + key controls
=========================================
[WAV] msg queue ready (USER_PWRKEY=1)
[WAV] playlist: 4 song(s)
[WAV]   [1] MUSIC.WAV     52920044 bytes
...
```

> 看到 `[WAV] playlist: N song(s)` —— 整个音频链路通了 🎉

### 4.4 失败排查

| 现象 | 跳到 |
|---|---|
| Downloader 报错 / 没识别板子 | [06 §1.5 半烧导致 dcf 损坏](06_踩坑大全.md) |
| 串口**完全无输出** | 检查 TX/RX 是否交叉、电平是不是 3.3V（不是 5V）、波特率 |
| 串口**输出乱码**（`????` `~~~~`） | 试试 8M 晶振 vs 16M 晶振的差异；问同事板子是什么晶振 |
| 看到 `SDK Vxx.xx` 但没有 `[WAV]` 块 | 进的是**别的 mode**，改 `main.c` 切换入口（[03_架构 §7 测试 Phase 切入点](03_SDK架构与运行模型.md)） |
| 卡在 `[WAV] playlist: 0 song(s)` | SD 卡格式不对，或音乐文件不在根目录 |

## 5. 跑 wav_test（20 分钟）

### 5.1 默认行为

**插着 SD 卡 + 接了喇叭** 启动后，应该立刻听到：

1. **0.5-1 秒静音**（系统初始化、SD 卡挂载）
2. 然后**开始播放**第一首 .WAV
3. **不按键** —— 整首播完，自动进下一首；播完最后一首回到第一首

### 5.2 测试 3 颗按键

| 键 | 短按效果 | 长按 |
|---|---|---|
| **S5 P/P** | 暂停 / 恢复（喇叭立刻静音 / 立刻恢复 — 这是正常的骤变，不是软故障） | 长按 1.2 秒会**软关机**（如果用 `KEY_PLAY_PWR_USER_DEF`） |
| **S6 PREV** | 切上一首（从头开始播） | 无特别 |
| **S7 NEXT** | 切下一首（从头开始播） | 无特别 |

### 5.3 串口 log 应该看到

按一次 P/P：

```
[WAV] key 0x0820 -> pause     ← KU_PLAY 短按
[WAV] key 0x0820 -> resume    ← 再按一次
```

> key code `0x0820` = `KU_PLAY`（详见 [04_按键系统完全指南 §5](04_按键系统完全指南.md)）

按一次 NEXT：

```
[WAV] key 0x0860 -> ...       ← KU_NEXT 短按
[WAV] pushed 4xxx bytes (xxxx frames) in 1000 ms   ← 没到 EOF 自然结束
[WAV] interrupted (next)
[WAV] slot 1 -> 2 (next)
```

### 5.4 完整通过标志

| 检查 | ✅ |
|---|---|
| 板子能正常播放第一个 WAV | ✅ |
| P/P 短按：暂停、再按：恢复 | ✅ |
| NEXT 短按：立刻播下一首 | ✅ |
| PREV 短按：立刻播上一首 | ✅ |
| 最后一首按 NEXT：回到第一首 | ✅ |
| 第一首按 PREV：跳到最后一首 | ✅ |
| 喇叭**左右均衡**、人声清晰、无"一边很小" | ✅ |
| 拔 SD 卡 → 串口输出错误日志（不卡死） | ✅ |

### 5.5 常见失败 → 跳

| 失败现象 | 跳到 |
|---|---|
| 完全没声音 | [06 §6 WAV 5 坑](06_踩坑大全.md) + `wav_test_02.md §3` |
| 一边声音很小 / 人声糊 | `wav_test_02.md §4`（v8 修复确认） |
| 按键全无反应、串口只看到 `0x07FE` 噪声 | [04 §6 系统事件过滤](04_按键系统完全指南.md) + [06 §2 芯片外设 10 坑](06_踩坑大全.md) |
| 按键按了立刻重启 | [06 §2 芯片外设](06_踩坑大全.md) + `wav_test_03.md §7.2`（WDT 没喂） |
| NEXT 没反应但 PREV/PLAY 正常 | [04 §4 防抖数学](04_按键系统完全指南.md) + `port_key.c:158-180` |
| 暂停用了几秒板子重启 | 同上（WDT 没喂狗） |

### 6.1 怎么切换 Phase

1. 打开 `app/projects/standard/main.c`
2. 搜函数 `wav_test_run()` —— 被注释掉的就是上一个 Phase 在用的入口
3. 找到对应 Phase 的入口函数名（看源文件顶部注释，例：`fat_test_run()` 或 `tf_test_run()`）
4. 注释掉 wav_test 的，启用新 Phase 的
5. **Build → Rebuild**（不是 Build）确保全重新编
6. 烧录新 .dcf

详细步骤见 [03 §7 测试 Phase 切入点](03_SDK架构与运行模型.md)。

## 8. （可选附录）10 个最低必要词汇

> 第一天**不需要**背下来 —— 看到时知道怎么查就行。建议**印刷一份贴桌边**，碰到不认识的词立即搜一次。

| 词 | 你需要知道的最小语义 | 详细在哪 |
|---|---|---|
| **SFR** (Special Function Register) | 芯片给每个外设**一块固定地址**，写它就是控制外设 | [02_芯片外设地图 §2](02_BT892XA2芯片与外设地图.md) |
| **BSS** | 未初始化全局变量，链接器统计 ≤ 13 KB | [02 §1 内存映射](02_BT892XA2芯片与外设地图.md) |
| **ISR** (Interrupt Service Routine) | 硬件自动跳进的函数，5ms 一次；**不能阻塞** | [03 §1 5ms tick](03_SDK架构与运行模型.md) |
| **WDT** (Watch Dog Timer) | 没人喂就 1-2 秒后重启整颗芯片 | [03 §3 WDT 分裂](03_SDK架构与运行模型.md) + [04 §10](04_按键系统完全指南.md) |
| **callback** | 你写的"被子系统调用"的函数指针 | [03 §9 func_cb](03_SDK架构与运行模型.md) |
| **mux** (multiplexer / 功能复用) | 一个引脚能干多件事（PA7 既能当普通 GPIO 也能当 UART TX） | [02 §5 FUNCMCON](02_BT892XA2芯片与外设地图.md) |
| **FAT32** | SD 卡的文件系统；分区表 + 文件分配表 | [fat入门指南.md](../fat入门指南.md) |
| **Petit FatFs** | ChaN 的极简 FAT 库，1 文件 1 卷，不能 LFN | [05_PetitFatFs §8](05_PetitFatFs源码导读.md) |
| **静态库** (.a) | 编译过的二进制，只给你 API 不给源码 | [03 §8 静态库边界](03_SDK架构与运行模型.md) |
| **FRESULT** | FatFs/Petit FatFs 的错误码枚举 | [05 §2 FRESULT 表](05_PetitFatFs源码导读.md) |
