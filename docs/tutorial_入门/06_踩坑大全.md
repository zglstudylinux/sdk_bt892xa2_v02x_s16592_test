## 1. 工具链 8 坑

> 详细工具链流程：[01_工具链与构建产物 §9](01_工具链与构建产物.md)

### 坑 T1：CB 不自动 glob — 源码进了目录但 build 不进 ELF

| | |
|---|---|
| **症状** | 自己新建 `examples/foo/foo.c`，但 build log 没看到 `Compiling: foo.c`，编译产物没它 |
| **根因** | Code::Blocks 不会扫子目录，所有源文件**必须显式** add 到 `.cbp` |
| **修法** | Project tab → 右键 `examples/` 文件夹 → **Add files recursively**（不是 Add directory） |
| **出处** | [01 §2](01_工具链与构建产物.md) |

### 坑 T2：13 KB BSS 超出 — link 时 `region 'ram' overflowed`

| | |
|---|---|
| **症状** | `riscv32-elf-gcc ... / ld ... region 'ram' overflowed by X bytes` |
| **根因** | static array 开太大（典型罪魁：`static u8 buf[8192];`） |
| **修法** | (1) 改用 `__attribute__((section(".aram")))` 把 buffer 放 aram；(2) 缩小 buffer；(3) 真正的"大内存"放 SD 卡 fat 段 |
| **出处** | [02 §1.3](02_BT892XA2芯片与外设地图.md) + `tf_test_summary §5.1` |

### 坑 T3：编译器警告 × 半死角 — 看似 build OK 实际未连

| | |
|---|---|
| **症状** | 编译过了，但跑起来调用函数**莫名进 hardfault**；map.txt 没新函数的记录 |
| **根因** | 函数被 `-Wl,--gc-sections` 切走了；如果又被 `-ffunction-sections` 区段化 |
| **修法** | (1) `__attribute__((used))` 防止优化掉；(2) 链脚本加 `KEEP(*(.text.func_name))` |
| **出处** | [01 §9.8](01_工具链与构建产物.md) |

### 坑 T4：Downloader 烧完 `.dcf` 是半文件 — 下次重烧不进

| | |
|---|---|
| **症状** | 同 .dcf 重烧 60% 卡死 / power drop 后板子变砖 |
| **根因** | DCF 镜像被截断，header magic 不完整 |
| **修法** | (1) 看 .dcf 长度是否符合预期 (~720KB)；(2) 重新 build 完整 .dcf 重烧；(3) BOOT 短接做"全片擦"有时能救 |
| **出处** | `AGENT_HANDOFF §6.2` + [06 §5](06_踩坑大全.md) |

### 坑 T5：`riscv32-elf-gcc: not found` 

| | |
|---|---|
| **症状** | build 第一个 .c 就失败 |
| **根因** | PATH 没设；或工具链装在别的目录但 CB profile 不匹配 |
| **修法** | (1) `which riscv32-elf-gcc`（Linux）或 PowerShell `where riscv32-elf-gcc`；(2) 加 PATH；(3) 检查 CB Compiler profile 的 Toolchain 路径 |
| **出处** | [01 §9.1](01_工具链与构建产物.md) |

### 坑 T6：postbuild.bat 失败 exit 1

| | |
|---|---|
| **症状** | Build 后报 "postbuild.bat failed" 不说原因 |
| **根因** | `%XMAKER%` 环境变量没设；或 .xm 有语法错 |
| **修法** | PowerShell 里手跑：`cd %~dp0; .\postbuild.bat` 看真实错 |
| **出处** | [01 §9.3](01_工具链与构建产物.md) |

### 坑 T7：DCF 烧入后没声音 — 错的 xcfg

| | |
|---|---|
| **症状** | 烧录 OK，HUART 有 banner，但 DAC 无输出 |
| **根因** | xcfg.bin 的若干项设错了 (`vol=0`, `mute=1`, `dac_dis=1`...) |
| **修法** | Downloader GUI 进去核对；或 hex 看 `xcfg.bin` |
| **出处** | [01 §1](01_工具链与构建产物.md) xcfg 表 |

### 坑 T8：build 改了 Hello 不生效 — 没 rebuild

| | |
|---|---|
| **症状** | 改了 `main()` 字符串 "Hello V2"，但跑出来还是 V1 |
| **根因** | 没按 Ctrl+F11 Rebuild；Ctrl+F9 是 Incremental Build (不会编译没改的文件) |
| **修法** | 改了**头文件**或 **config** 后一定 Rebuild |
| **出处** | [01 §7](01_工具链与构建产物.md) |

## 2. 芯片外设 10 坑

> 详细 SFR / GPIO 介绍：[02_BT892XA2芯片与外设地图](02_BT892XA2芯片与外设地图.md)

### 坑 C1：GPIO 被外设占用 → 写 1 被默默忽略

| | |
|---|---|
| **症状** | `bsp_gpio_cfg_init + gpio_set(1)` 后万用表 / 示波器测脚没变 |
| **根因** | FUNCMCON 没切；该 IO 默认归属别的外设 |
| **修法** | 用 `bsp_gpio_cfg_init(&g, IO_PD0)` —— 它**自动**切 |
| **出处** | [02 §5](02_BT892XA2芯片与外设地图.md) |

### 坑 C2：47K 高阻源按键被防抖吞掉 — 实测值精确 = 0 裕量阈值

| | |
|---|---|
| **症状** | S7 NEXT 按 100 次都没 log / P/P 和 PREV 完全正常 |
| **根因** | 47K 高阻源 ADC 噪声 ±3-5 LSB，6×5ms 防抖永远计不到 6 次 |
| **修法** | 阈值 = 实测值 + **至少 18 LSB**（实测 0xD3 → 阈值 0xE5） |
| **出处** | [04 §4](04_按键系统完全指南.md) + `wav_test_03 §7.4` |

### 坑 C3：WDT 在 func_* 框架外不喂狗 → 1-2s 重启

| | |
|---|---|
| **症状** | 按 P/P 一两秒后整颗芯片 reset；log 显示完整 cycle 又重启 |
| **根因** | 测试主循环 (`wav_test_run`) 不在 `func_process` 内，没人调 `WDT_CLR` |
| **修法** | 测试主循环**每 100 ms**调一次 `WDT_CLR()`（用 `tick_get()` 计） |
| **出处** | [03 §3](03_SDK架构与运行模型.md) + `wav_test_03 §7.2` |

### 坑 C4：`USER_PWRKEY=1` 编译开了，但 runtime 不响应

| | |
|---|---|
| **症状** | build OK，按键不响应 |
| **根因** | (1) `USER_PWRKEY=0` 编译时关；或 (2) `xcfg_cb.user_pwrkey_en = False` runtime 关。两开关都开才行 |
| **修法** | config.h 改 `USER_PWRKEY 1`；Downloader GUI 翻 `user_pwrkey_en=True` |
| **出处** | [04 §7](04_按键系统完全指南.md) + `wav_test_03 §5.4` + `Boombox.setting:121` |

### 坑 C5：`KEY_PLAY_PWR_USER_DEF` 长按 1.2s 触发 FUNC_PWROFF

| | |
|---|---|
| **症状** | P/P 按 1.2 秒后整颗芯片"软关机" |
| **根因** | func.c:298-310 直接对 KLH_* PWR family 切 `FUNC_PWROFF` |
| **修法** | P/P 用 plain `KEY_PLAY=0x20`，不用 PLAY_PWR_USER_DEF（除非确实要长按关） |
| **出处** | [04 §8](04_按键系统完全指南.md) |

### 坑 C6：FUNCMCON 设了，IO 还是不响应

| | |
|---|---|
| **症状** | 切换 FUNCMCON 后 IO 仍无效 |
| **根因** | DIR/DE/PU 没配合设；或上一次的 FUNCMCON bitmap 错了 |
| **修法** | 用 SDK 的 `bsp_gpio_cfg_init` 而不是手动 FUNCMCON |
| **出处** | [02 §4-5](02_BT892XA2芯片与外设地图.md) |

### 坑 C7：`saradc_setup_time_set` 是空宏 — 高阻源没建立时间

| | |
|---|---|
| **症状** | 47K / 100K 按键即便放宽阈值仍不稳 |
| **根因** | `api_saradc.h:10` 定义了宏但内部 noop；注释说要 N us 实际没加 |
| **修法** | (1) 不用 47K 以上电阻；(2) 自己加 `delay_us(100)` 在 `adc_get_value` 之前 |
| **出处** | [04 §2.5](04_按键系统完全指南.md) + [02 §7](02_BT892XA2芯片与外设地图.md) |

### 坑 C8：WKO 共享脚被 SD 卡悄悄占用

| | |
|---|---|
| **症状** | `pff_mount` 一次后，pwrkey ADC 读出奇低（≈0） |
| **根因** | 默认 PD 端口可能归属 SDIO；FUNCMCON 没切 |
| **修法** | pff_mount 完调 `bsp_gpio_cfg_init(&g, IO_PBx)` 设 pwrkey IO 回 GPIO |
| **出处** | `tf_test_summary §4.2` |

### 坑 C9：rctcon0 / 触摸通道持续生效 → 影响 ADKEY 上电值

| | |
|---|---|
| **症状** | 上电后 ADC 实测值偏低；重烧 adkey 例程能恢复 |
| **根因** | `rtccon0` 掉电保存，某些 SDK 启动不重置；同时触摸通道漏关 |
| **修法** | 启动时主动 `adcch_io_pu10k_enable + touch_disable` |
| **出处** | `test/参考.md:251` (徐奕濠) |

### 坑 C10：清 WDT 错 — 写 0xA 不是 0

| | |
|---|---|
| **症状** | 自己写 `WDTCON = 0;` 以为清狗，但 watchdog 还是 fire |
| **根因** | `WDT_CLR` 宏实际是 `WDTCON = 0x0A`，约定值不是 0 |
| **修法** | 用 SDK 的 `WDT_CLR()` 宏（`macro.h:17-21`），不要自己写寄存器 |
| **出处** | [02 §10.5](02_BT892XA2芯片与外设地图.md) + [03 §3](03_SDK架构与运行模型.md) |

## 3. SDK 架构 6 坑

> 详细 5ms ISR / msg / func_run：[03_SDK架构与运行模型](03_SDK架构与运行模型.md)

### 坑 S1：紧循环忘 `msg_dequeue` → ISR 塞的键没机会消费

| | |
|---|---|
| **症状** | 按键完全无响应；log 只看到 0x07FE 周期噪声 |
| **根因** | 自写的 main while() 里没 `msg_dequeue()` |
| **修法** | 每圈加 `u16 msg = msg_dequeue(); if (msg) handle(msg);` |
| **出处** | [03 §2](03_SDK架构与运行模型.md) |

### 坑 S2：忘系统事件过滤 → 队列被 0x07xx 占满

| | |
|---|---|
| **症状** | 同样：按键失灵 |
| **根因** | dispatch 没过滤 `(msg & 0xFF00) == 0x0700` |
| **修法** | 头部加 `if (msg < 0x100 || (msg & 0xFF00) == 0x0700) return;` |
| **出处** | [04 §6](04_按键系统完全指南.md) + [03 §2.3](03_SDK架构与运行模型.md) |

### 坑 S3：`KU_PLAY_PWR_USER_DEF` 实际进 switch 后立刻 FUNC_PWROFF

| | |
|---|---|
| **症状** | （同 C5）功能表现像是 dispatch 错了 |
| **根因** | long press 提前被 func.c 切走了 |
| **修法** | 短按路径 KID 不是 `KEY_PLAY_PWR_USER_DEF` |
| **出处** | [04 §8](04_按键系统完全指南.md) |

### 坑 S4：5 ms ISR 延迟假设 → 实际是 5 ms 抖

| | |
|---|---|
| **症状** | 想"每 5 ms 干一件事"但发现偶尔 6-7 ms |
| **根因** | 5 ms tick 是硬件定时器，分辨率受 PLL 影响 ±10% |
| **修法** | 不要依赖精确 5 ms；用绝对 `tick_get()` 比较 |
| **出处** | [03 §1](03_SDK架构与运行模型.md) |

### 坑 S5：`delay_5ms(N)` vs `delay_us(N)` 混用 → 暂停期间 ISR 饿死

| | |
|---|---|
| **症状** | 暂停期间按音量键没反应；只 5ms 后才能响应 |
| **根因** | `delay_ms(200)` 太久，ISR 200ms 内没法跑 |
| **修法** | 暂停用 `delay_us(200)` 让出 CPU，不到 1 ms 一次醒来 |
| **出处** | [04 §6](04_按键系统完全指南.md) |

### 坑 S6：加新 func_* 时 enum / switch / header 三处都得改

| | |
|---|---|
| **症状** | 加了 `func_foo.c` 但 build 不进 |
| **根因** | enum 加了但 func.c switch 没加 case |
| **修法** | 5 步全改（详见 [03 §10](03_SDK架构与运行模型.md)） |
| **出处** | [03 §10](03_SDK架构与运行模型.md) |

## 4. Petit FatFs 8 坑

> 详细 pff 源码：[05_PetitFatFs源码导读](05_PetitFatFs源码导读.md)

### 坑 F1：include 顺序错 — `FRESULT redefinition`

| | |
|---|---|
| **症状** | pff.h 和 api_fs.h 都有 FRESULT enum，编译报 redefined |
| **根因** | `#include "pff.h"` 先于 `#include "include.h"` |
| **修法** | wav_test.c:41-43 顺序（先 include.h 后 pff.h）|
| **出处** | [05 §6](05_PetitFatFs源码导读.md) + `fat_test_summary §4.1` |

### 坑 F2：`disk_initialize undefined` 多重定义

| | |
|---|---|
| **症状** | link 时 `disk_initialize` 既在 pff.c 也在 libdrivers.a |
| **根因** | 没 `pff_compat.h` 重命名 |
| **修法** | 加 `pff_compat.h`，所有 `disk_* → pff_disk_*` |
| **出处** | [05 §6](05_PetitFatFs源码导读.md) |

### 坑 F3：注释里的 `*/` 提前结束 — 编译大段 green out

| | |
|---|---|
| **症状** | 编译报 "unterminated comment" |
| **根因** | 注释字符串里出现 `*/` 序列 |
| **修法** | 删字或改 `/* *\/ */` 之类 |
| **出处** | `fat_test_summary §4.1` (case 3) |

### 坑 F4：partial-sector cache 漏写

| | |
|---|---|
| **症状** | `disk_readp(buf, lba, 5, 4)` 拿到错字节 |
| **根因** | cache 没装 cache 直接 memcpy |
| **修法** | pff_compat 重写的 disk_readp 必须先 sd0_read(整扇区) 到 cache |
| **出处** | [05 §5](05_PetitFatFs源码导读.md) |

### 坑 F5：把 LFN 文件夹当 SFN 处理 → 乱码文件名

| | |
|---|---|
| **症状** | PC 拷到 SD 的文件读不到；log 文件名是 "捝4懒9" 类奇怪字符 |
| **根因** | Petit FatFs 不解析 LFN（带 0x0F 属性的目录项），但**不自动过滤**它们 |
| **修法** | 显式 `if (fattrib & AM_LFN) continue;` |
| **出处** | [05 §4.5](05_PetitFatFs源码导读.md) + wav_test.c:208 |

### 坑 F6：`PF_USE_LSEEK=0` 但调了 pff_lseek

| | |
|---|---|
| **症状** | `pff_lseek` unresolved reference |
| **根因** | pffconf.h 没开这个 |
| **修法** | pffconf.h 加 `#define PF_USE_LSEEK 1` |
| **出处** | [05 §3](05_PetitFatFs源码导读.md) |

### 坑 F7：写文件用 pf_write 但 PF_USE_WRITE=0

| | |
|---|---|
| **症状** | 运行时 PF_USE_WRITE=0 → FR_NOT_ENABLED |
| **根因** | pffconf.h 没开 PF_USE_WRITE |
| **修法** | pffconf.h 加 `#define PF_USE_WRITE 1` |
| **出处** | [05 §3](05_PetitFatFs源码导读.md) |

### 坑 F8：双向读写同一文件（Petit 不支持）

| | |
|---|---|
| **症状** | 打开两个 file，使用同一个 cache buffer，读写混乱 |
| **根因** | Petit FatFs 一次只允许打开 1 个文件 |
| **修法** | (1) 设计上分次打开；(2) 真要并发 → 换 full FatFs |
| **出处** | [05 §8](05_PetitFatFs源码导读.md) |

## 5. SD 卡 6 坑

> 详细 SD 协议：`tf_test_01_02.md` ~ `tf_test_07.md`

### 坑 SD1：superfloppy 格式（小卡）→ 把 VBR 当 MBR 解析

| | |
|---|---|
| **症状** | 16G 以下小卡挂载时算出的 fat_start = 错地址 |
| **根因** | 卡上没 MBR，LBA 0 直接是 VBR |
| **修法** | bps=0 或 bps 异常时 fallback 到 LBA 0 直接解析为 VBR |
| **出处** | `tf_test_summary §3.2` + `test/参考.md:46` (何平) |

### 坑 SD2：SD 波特率太低 → "噗噗噗" 杂音

| | |
|---|---|
| **症状** | wav 播放有杂音、断流 |
| **根因** | SD 时钟 < 2 MHz；内置 DMA 跟不上解码节奏 |
| **修法** | 把 SD 时钟拉到 8-12 MHz；用 DMA（不是 PIO） |
| **出处** | `test/参考.md:129` (李宗霖) + `test/参考.md:110` (杜鹏) |

### 坑 SD3：写后忘 busy 轮询 → data 写一半

| | |
|---|
| **症状** | 文件写完关闭，下次打开内容错位 |
| **根因** | SD 写入后内部 busy 没等完，CPU 读卡返回早 |
| **修法** | 写后 `while (CMD13_busy != 0)` |
| **出处** | `tf_test_summary §3.5` |

### 坑 SD4：CMD25 stop token 错 — 卡死了

| | |
|---|---|
| **症状** | 多块写完停了但卡还 busy；后续 CMD 错误 |
| **根因** | 漏发 0xFD stop token，或没补发 CMD12 |
| **修法** | `CMD25 → while (data block) → 0xFD → CMD12` |
| **出处** | `tf_test_05.md §5` + `tf_test_07.md` |

### 坑 SD5：FUNCMCON 没清 → 控制器默默占用脚

| | |
|---|---|
| **症状** | pff_mount 后卡 init 失败 |
| **根因** | 默认 PE5/6/7 是 SDIO 线；如果你的代码也用它们做 GPIO 但没切 |
| **修法** | `bsp_sd0_init()` 后不要直接复用那几个 IO；或者 `SDx_MUX_IO_INIT(0)` |
| **出处** | `tf_test_summary §4.2` |

### 坑 SD6：SD 卡读取不够快 → 音质断续

| | |
|---|---|
| **症状** | 一个 512 字节 block 之后下个 block 还没读到 → DAC 静音一段 |
| **根因** | 一次性读太少（≤512 字节），每次都要等 SD 卡 |
| **修法** | (1) 用 512 B + AUBUFDATA 满不等；(2) 链表/环形 buffer；(3) 升 SD 时钟 |
| **出处** | `test/参考.md:40` (何梓江：14 KB buffer 解决) + `test/参考.md:113` (李宗霖：12 M 时钟) |

## 6. WAV 5 坑

> 详细 WAV：`wav_test_01.md`/`wav_test_02.md`/`wav_test_03.md`

### 坑 W1：chunk walker 漏 LIST/JUNK → 走不到 data

| | |
|---|---|
| **症状** | 某些文件（iTunes 拷出的）找不到 data chunk |
| **根因** | "LIST"、"JUNK"、"fact" 等非数据 chunk 不知道跳过 |
| **修法** | walker 不限定 id，只看每个 chunk size 跳过去 |
| **出处** | wav_test_02.md + `test/参考.md:88` (陈铎隆) |

### 坑 W2：暂停"写 0 推 DAC" → 有 pop

| | |
|---|---|
| **症状** | 按 P/P 喇嘛"噗"一声 |
| **根因** | 暂停时把 0 推进 DACBUF，突然的直流分量 |
| **修法** | 暂停期间**不写** DACBUF，仅 delay + 查消息 |
| **出处** | `wav_test_03.md §3.3` + `test/参考.md:12` (李光超) + `test/参考.md:135` (杜鹏) |

### 坑 W3：24/32-bit 强压 16-bit → 音质差

| | |
|---|---|
| **症状** | 24-bit WAV 强压 16-bit 时音量畸变 |
| **根因** | 16-bit dynamic range 没法装 24-bit 跨度 |
| **修法** | (1) 用 Audacity 转 16-bit；(2) 真的需要 24-bit：扩 SDK DAC 路径 |
| **出处** | `test/参考.md:244` (李坪臻) + `test/参考.md:274` (姚嘉隆) |

### 坑 W4：没做 RIFF/WAVE magic check → 当 raw 文件播

| | |
|---|---|
| **症状** | 用 .txt 当 .wav 文件播放，喇嘛叫 |
| **根因** | 缺 `0x46464952 'RIFF'` `0x45564157 'WAVE'` magic check |
| **修法** | `rd32(buf+0) == 0x46464952 && rd32(buf+8) == 0x45564157` |
| **出处** | wav_test_01.md + wav_test_02.md |

### 坑 W5：采样率混淆 — SPR_44100 ≠ 44100

| | |
|---|---|
| **症状** | wav 播放速度全乱（2x/0.5x）|
| **根因** | `dac_spr_set(44100)` — 实际 SDK 不收数字，要传 SPR 枚举 |
| **修法** | `dac_spr_set(SPR_44100)` |
| **出处** | wav_test_02.md + `test/参考.md:324` (金国强) + 多人提 |

### 7.2 仅在原心得详述的高频子集（不重复）

> 这些**没集成到上面 §1-6**——上面已经够长。具体做法**只在 `test/参考.md` 有详述**：

#### 7.2.1 **手动实现 my_sd_read 绕过闭源 `fs_read`**

来源：龙宇阳 [test/参考.md:55](../test/参考.md)

实测了 SDK 闭源 `fs_read` 在 DMA 放音时**每次调都有几 ms 卡顿**，波形畸变。修法：**直接走自己的 sd0_read + 512B buffer**（可不通过 pff_read）——针对纯 WAV 播放场景。

> **适用**：你只跑 WAV，且发现 DAC 有 1/2/3 帧畸变。这是少数值得绕路 fs_* 闭源的情况。

#### 7.2.2 **实现在 dal_pause="ms" 期间 dac_put_zero(256) 渐静音**

来源：李宗霖 [test/参考.md:135](../test/参考.md)

```c
/* pause 时先 dac_put_zero(256) 预填静音，然后空 gap 即可 */
```

> 与我们 wav_test.c 的"暂停时不写 0"做法不冲突 —— 他们是"先 256 次零"再"空了"，我们是"完全空"。两种都对。

#### 7.2.3 **`bsp_dac_ext.c` 移植到 mini 工程时常漏 `CLKCON1 |= 0x01`**

来源：李坪臻 [test/参考.md:240](../test/参考.md) + 卜永健 [test/参考.md:308](../test/参考.md)

DAC 时钟寄存器在 `bsp_dac_ext.c` 移植到 mini 必须开，否则 `dac_*` 直接卡死。

#### 7.2.4 **`dac_aubuf_init + dac_fade_in + dac_ang_gain_set(ANL_N6DB) + dac_vol_set + dac_put_zero(256)` 完整播放前**

来源：何平 [test/参考.md:50](../test/参考.md)

完整 5 步 DAC 上电序列，**不是只 `dac_spr_set`**。少一步 (e.g. 忘 `dac_fade_in`) → DAC 静音。

#### 7.2.5 **14 KB SD buffer 后音质干净（vs 512B）**

来源：何梓江 [test/参考.md:40](../test/参考.md)

实测 14 KB x 2 个 ping-pong buffer + 12M SD 时钟 → 音质"听感正常"。**vs.** 杜鹏的 512B + 2M SD，"听感可接受但杂音"。

> 经验值：buffer ≥ 4KB + SD 时钟 ≥ 8M 是及格线。

#### 7.2.6 **`fsdisk_callback_init(0)` + `fs_var_init` + `fs_mount` 流程**

来源：张愈朗 [test/参考.md:30](../test/参考.md)

BT987X 系列 SDK（不是 892）的 fs_* 用法，**和我们的 pff_mount 完全不同**。这条心得**不能套**到我们 BT892XA2 工程。
