## 1. 这个 SDK 是什么

**BT892XA2** 是中科蓝讯（Bluetrum）推出的一款 **RISC-V 32-bit 蓝牙音频 SoC**，内置 CPU、蓝牙基带、音频 DAC、电源管理等模块，主要用于 TWS 耳机、蓝牙音箱等小型音频产品。本仓库的 SDK 是它的 **V020.0** 版本（[app/platform/header/config_extra.h:8](../app/platform/header/config_extra.h#L8)）。

整套 SDK 由两部分组成：

| 部分 | 路径 | 说明 |
|---|---|---|
| **平台 SDK** | [app/platform/](../app/platform/) | 操作系统、BSP、驱动、蓝牙协议栈、编解码库等，**多数以预编译静态库形式提供**（`libplatform.a`、`libbtstack.a`、`libcodecs.a`、`libdrivers.a`、`libvoices.a`） |
| **示例工程** | [app/projects/](../app/projects/) | 两个完整的客户工程：`standard`（通用蓝牙音箱）、`earphone`（TWS 耳机） |

**核心特点**：

- **RISC-V 32-bit 自定义 ISA**（`-march=rv32imacxbs1`），CPU 内核是定制款而非标准 RISC-V
- **闭源静态库 + 开放应用层**：用户改的是 `port/`（板级）和 `plugin/`（产品功能），驱动和协议栈在 `.a` 里看不到源码
- **可视化配置系统**：所有功能开关（蓝牙名称、LED 指示、音量曲线、引脚映射等）通过 `xcfg.xm` 配置，自动生成 `xcfg.h` 和二进制 `xcfg.bin`，可在 Downloader 里在线改
- **打包容器 `.dcf`**：编译产物不是普通的 `.bin`/`.hex`，而是一个带 `DCF\0` 头的容器，里面装 `header + app + res + xcfg + updater` 五段数据

> **简言之**：这个 SDK 是为**产品工程师**服务的，不是教学型 SDK。你要做的不是"理解芯片每个寄存器"，而是"读懂 SDK 的应用框架，改动你板子相关的部分"。

## 2. 5 分钟快速上手

如果你只想跑通"打开工程 → 编译 → 下载"三步，follow 这一节即可。

### 2.1 需要的工具（如果你还没装，向中科蓝讯索取）

| 工具 | 说明 |
|---|---|
| **Code::Blocks** | IDE，打开 `.cbp` 工程文件。本仓库使用自定义编译器 profile 名 `riscv32`，需在 CB 全局编译器配置里指向 `riscv32-elf-gcc.exe` 所在目录 |
| **riscv32-elf-gcc** | 交叉编译工具链（GCC 系）。命名风格 `riscv32-elf-gcc`、`riscv32-elf-objcopy`、`riscv32-elf-ld` |
| **riscv32-elf-xmaker** | 中科蓝讯自研工具，编译 `.xm` 脚本（生成 `xcfg.bin`、`res.bin`）和打包 `.dcf` |
| **Downloader** | 烧录工具，Windows GUI，通过 UART 把 `.dcf` 写入芯片 flash |

工具链的具体版本和安装路径，**SDK 里没有写**——这是中科蓝讯发给客户时单独配的，你得问他们要。

### 2.2 打开工程

```
双击  app/projects/standard/app.cbp       ← 通用蓝牙音箱（推荐新手从这个开始）
或     app/projects/earphone/app.cbp      ← TWS 耳机（更复杂，含 ANC）
```

Code::Blocks 加载工程，左侧 Management 面板会列出几十个 `.c` 文件 + 编译选项。

### 2.3 编译

- 菜单 **Build → Build**（或 Ctrl+F9）
- 等待进度条，**第一次编译 1-2 分钟**，之后增量编译几秒
- 看到 `Output/bin/app.dcf` 时间戳更新即成功

### 2.4 烧录 + 观察

1. 用 USB 转 UART（通常是 PA7 / PB2 / PB3）接上板子
2. 打开 Downloader → 选 `Output/bin/app.dcf`
3. 按住板子的 **BOOT / DOWNLOAD** 键（或拉低某个特定 GPIO）→ 上电 → 进下载模式
4. Downloader 点"下载" → 烧录完成 → 重启芯片
5. 观察现象（按键、TF 卡检测、蓝牙广播、播放音乐……）

## 3. 工具链详解

SDK 的工具链结构画出来是：

```
┌──────────────┐
│  .c 源文件    │
│  .h 头文件    │
│  .xm 脚本    │  ← xmaker 的输入（伪 C 脚本，用 C 预处理器展开宏）
└──────┬───────┘
       │
       ▼  prebuild.bat（Build 前自动跑）
┌──────────────────────┐
│ riscv32-elf-xmaker   │
│   -b res.xm          │  → res.bin  + res.h  + res/*.mp3 进 Output/bin/res/
│   -b res2.xm [optional]
│   -b xcfg.xm         │  → xcfg.bin + xcfg.h + Settings/*.setting
└──────┬───────────────┘
       │
       ▼  Code::Blocks 编译每个 .c 单元
┌──────────────────────┐
│ riscv32-elf-gcc      │
│   -march=rv32imacxbs1│  → .o 文件到 Output/obj/
│   -ffunction-sections│
│   -msave-restore     │
└──────┬───────────────┘
       │
       ▼  Code::Blocks 链接
┌──────────────────────┐
│ riscv32-elf-ld       │
│   -T ram.o           │  → Output/bin/app.rv32（ELF 格式）
│   --gc-sections      │     + map.txt（链接器映射，可看每个函数占多大）
│   -Map=...           │
└──────┬───────────────┘
       │
       ▼  postbuild.bat（Build 后自动跑）
┌──────────────────────┐
│ riscv32-elf-objcopy  │  app.rv32 → app.bin（纯二进制，去掉 ELF 头）
│ riscv32-elf-xmaker   │  appxm.o (预处理过的 app.xm) 调用 make(...) 打 .dcf
│   -b appxm.o         │     make(header.bin, app.bin, res.bin, xcfg.bin, updater.bin) → app.dcf
│ [C:\upload\upload.bat]│  内部上传脚本（通常不存在，无副作用）
│ riscv32-elf-xmaker   │
│   -b download.xm     │  自动下载钩子（依赖 Downloader 实际通信）
└──────┬───────────────┘
       │
       ▼
   Output/bin/app.dcf   ← 你拿去烧录的最终产物
```

### 3.1 `.xm` 文件是什么鬼？

`.xm` 是 **扩展 C 脚本**——语法上像 C，但实际不会编译成机器码。它由 `xmaker` 解释执行，配合 **C 预处理器**（`gcc -E -P -x c`）先展开宏。所以你能在 `.xm` 里写：

```c
// app/projects/standard/Output/bin/app.xm
#include "config.h"          // ← 普通 C include
depend(0x010200);
setflash(1, FLASH_SIZE, FLASH_ERASE_4K, FLASH_DUAL_READ, FLASH_QUAD_READ);
make(dcf_buf, header.bin, app.bin, res.bin, xcfg.bin, updater.bin);
save(dcf_buf, app.dcf);
```

预处理时，`FLASH_SIZE` 这种宏会被展开成数字，然后 xmaker 解释执行 `depend()`、`setflash()`、`make()` 等"打包指令"。

`app.xm` 的位置：`app/projects/<工程>/Output/bin/app.xm`（每工程一个）

### 3.2 `.dcf` 文件结构

```
偏移  内容       说明
0x00  "DCF\0"    魔数（4 字节）
0x04  版本号     little-endian
...   SMAT\0     配置元数据段（语言、固件版本等）
...   SUB.\0     子段容器
...   LST.\0     文件清单（包含 app.bin / res.bin / xcfg.bin / updater.bin）
```

用十六进制编辑器打开 `Output/bin/app.dcf`，前 4 字节一定是 `44 43 46 00`。

## 4. 完整编译下载流程

### 4.1 从源码到 `.dcf`（Code::Blocks 一键完成）

```
1. 打开 app/projects/standard/app.cbp
2. Build → Build (Ctrl+F9)
3. 看 Output/bin/app.dcf 时间戳是否更新
4. 文件大小典型值：700~800 KB（包含完整蓝牙协议栈 + 资源）
```

### 4.2 从 `.dcf` 到芯片

```
5. 启动 Downloader（PC 工具，通常中科蓝讯随 SDK 一并发）
6. File → Open → 选 app.dcf
7. Downloader 解析 .dcf，显示 .dcf 内嵌的配置项（这些就是 xcfg 暴露给用户的可选项）
8. 根据你的板子，必要时修改：
   - 蓝牙名称、MAC 地址
   - LED 指示灯极性
   - 按键映射
   - 音频 EQ 预设
   - 是否勾选"擦除"或"保持"（保持 = 保留 flash 里旧的蓝牙地址/校准数据）
9. 让板子进入下载模式（一般需按住某个键 + 上电 / 拉低某个 GPIO）
10. Downloader 点"下载" → 进度条 → 完成后自动重启芯片
11. 观察现象：按按键、插卡、连蓝牙……
```

### 4.3 调试串口（HUART）

如果你要调试，需要从芯片引出一根 **调试 UART**：

- 在 `config.h` 里设置 `HUART_EN = 1`，选个空闲引脚（如 `HUART_SEL = IO_PA7`）
- 这根线在芯片运行时输出 `printf()` 内容
- PC 端用串口助手（115200 8N1）接收

**注意**：调试 UART 选错了引脚会和 SD 卡 / USB 冲突。`config_extra.h` 第 723-781 行有自动互斥逻辑。

### 6.1 芯片上电后发生了什么

### 6.2 func_cb.sta 的状态机

`func_cb.sta` 是 SDK 全局状态变量（定义在 `func.c:3`），由消息队列、`xcfg_cb`、各种事件来改变。比如：

- 用户按 MODE 键 → `msg_enqueue(KU_MODE)` → `func_message()` 把 `func_cb.sta = FUNC_NULL` → 下次 `func_exit()` 切到下一个模式
- 检测到 TF 卡插入 → 触发 `EVT_SD_INSERT` 消息 → `func_cb.sta = FUNC_MUSIC`
- 按住 POWER 键 3 秒 → `func_cb.sta = FUNC_PWROFF`

### 6.3 主要 func_\* 的职责

| Func | 职责 |
|---|---|
| `func_bt()` | 蓝牙模式：A2DP 音频、AVRCP 控制、HFP 通话 |
| `func_music()` | 本地音乐播放：解码 WAV/MP3/AAC/FLAC/APE、控制播放进度、ID3 显示 |
| `func_aux()` | LineIn 直通或 AUX ADC |
| `func_clock()` | 闹钟模式（独立线程） |
| `func_spdif()` | SPDIF 数字音频输入 |
| `func_idle()` | 空闲模式，**适合做实验 / 调试**——它什么都不做，只是一个 while(1) 循环 |
| `func_pwroff()` | 软关机流程 |
| `func_sleepmode()` | 深度睡眠 |
| `func_usbdev()` | USB device 模式（读卡器 / USB 声卡） |
| `func_update()` | OTA 升级流程 |

### 6.4 全局回调注册

`func_cb` 结构体里塞了大量回调函数指针，应用层可注册：

```c
func_cb.mp3_res_play = my_mp3_player;   // 注册提示音播放器
func_cb.set_vol_callback = my_vol_hook; // 注册音量变更钩子
func_cb.sta = FUNC_BT;                  // 启动后进入蓝牙模式
```

## 7. 改哪里？怎么改？

### 7.1 决策树：你这次想改什么？

```
想改什么？
│
├─ 板子上的引脚配置（TF 卡用哪个 pin？LED 接到哪？）
│   └─→ 改 port/port_*.c
│
├─ 加/减某个功能（要不要支持 FM 收音机？要不要 ANC？）
│   └─→ 改 config.h 里相应的 *_EN 宏
│
├─ 蓝牙名称 / 提示音语言 / LED 极性 等可视化参数
│   └─→ 改 Output/bin/xcfg.xm
│
├─ 加一个按键动作（比如"长按 PLAY 切换 EQ"）
│   └─→ 改 message/msg_*.c
│
├─ 改 EQ / 音量曲线 / 滤波
│   └─→ 改 plugin/eq_table.c 或 plugin/multi_lang.c
│
└─ 改 DAC 输出逻辑 / 加自定义音频处理
    └─→ 在 func_music.c 或新文件里 hook DAC 回调
```

### 7.2 改 `port/port_earphone.c` —— 引脚映射总表

打开 [app/projects/standard/port/port_earphone.c](../app/projects/standard/port/port_earphone.c)，里面通常是 `bsp_gpio_cfg_init(g, xcfg_cb.xxx_iosel)` 这种模式——引脚号从 `xcfg_cb`（由 xcfg 工具生成的可视化配置）里读取，而不是硬编码。

### 7.3 改 `config.h` —— 功能开关

[app/projects/standard/config.h](../app/projects/standard/config.h) 是一个 49 KB 的巨文件，每个宏都有中文注释。例如：

```c
#define FUNC_BT_EN                 1     //蓝牙模式开关
#define FUNC_MUSIC_EN              1     //本地音乐播放开关
#define MUSIC_SDCARD_EN            1     //TF 卡支持开关
#define MUSIC_UDISK_EN             0     //U 盘支持开关
#define BT_TWS_EN                  0     //TWS 主从开关
#define ANC_EN                     0     //主动降噪开关
```

把开关翻成 0/1，触发对应模块的代码被条件编译包含/排除。**注意**：很多宏会自动联动（`config_extra.h` 第 723-781 行），改之前先看看有没有 `#error` 检查。

### 7.4 改 `xcfg.xm` —— 可视化配置

[app/projects/standard/Output/bin/xcfg.xm](../app/projects/standard/Output/bin/xcfg.xm) 是中科蓝讯自家的"配置 DSL"，每个 `config(...)` 调用对应 Downloader 里的一行可选项：

```c
config(bt_name: string, "Bluetrum-SPK", "蓝牙名称");
config(led_polarity: 0, "LED 极性 0=低点亮");
config(eq_default: 0, "默认 EQ 0=Normal 1=Bass 2=Rock...");
```

改完 xcfg.xm 后，Build 时 prebuild.bat 会自动跑 `xmaker -b xcfg.xm`，生成新的 `xcfg.h` 和 `xcfg.bin`——你的 C 代码引用 `xcfg_cb.bt_name` 就拿到新值了。

### 7.5 加按键动作

每个模式有自己的消息处理文件：

```
message/msg_bt.c        蓝牙模式下的按键
message/msg_music.c      音乐模式下的按键
message/msg_aux.c        AUX 模式下的按键
...
```

打开 [app/projects/standard/message/msg_music.c](../app/projects/standard/message/msg_music.c)，可以看到大量 `case KU_PLAY:` 这种 switch 分支。加新动作就在这里 `case` 然后写处理。

## 10. 常见问题排查

### Q1：Code::Blocks Build 失败，提示找不到 `riscv32-elf-gcc`

Code::Blocks 不知道你的工具链路径。修法：

1. 菜单 Settings → Compiler
2. 选 "riscv32" profile（如果列表没有，需要 copy 一份 "GNU GCC Compiler" 重命名）
3. 设置 "Compiler's installation directory" 指向 `riscv32-elf-gcc.exe` 所在目录
4. 确认 "Toolchain executables" tab 里的 `gcc`、`g++`、`ld`、`objcopy` 都已填好

### Q2：Build 成功但 `Output/bin/app.dcf` 没有生成

1. 看 Build log 末尾有没有报错
2. 打开 [Output/bin/postbuild.bat](../app/projects/standard/Output/bin/postbuild.bat)，手动跑一遍：
   ```
   cd app\projects\standard\Output\bin
   postbuild.bat standard
   ```
   看哪步失败
3. 常见原因：`riscv32-elf-objcopy` 不在 PATH 里

### Q3：Downloader 烧录后芯片没反应

1. 检查是否真的进了下载模式（一般要按住某个键或短接某个 GPIO）
2. UART 线接反了？TX↔RX 交叉一下
3. Downloader 里选的端口错了
4. 试一下 `.dcf` 文件能不能在 Downloader 里正常打开（如果打不开说明 .dcf 损坏了）

### Q4：串口没输出

1. `config.h` 里 `HUART_EN = 1` 了吗？
2. `HUART_SEL` 选的引脚和你实际接的对吗？
3. 串口助手波特率对了吗？（SDK 默认 115200 8N1）
4. `UART0_PRINTF_SEL` 设为 `PRINTF_NONE` 了吗？看 `config_extra.h:758-781` 自动重定义逻辑

### Q5：TF 卡不识别

1. `MUSIC_SDCARD_EN = 1` 了吗？
2. `SD0_MAPPING`（在 xcfg 里选）和你板子的 SD 卡 pin 一致吗？
3. 用万用表量一下 SD 卡槽的 CLK 引脚，芯片初始化 SD 卡时应该有 100kHz 左右的方波
4. 卡是不是格式化成 FAT16/FAT32？exFAT 不支持

### Q6：蓝牙连不上

1. 蓝牙名称是否包含中文（部分手机识别不好）
2. `BT_NAME` 长度是不是超过了 18 字符
3. 看一下 `Output/bin/app.dcf` 里 `xcfg.bt_name` 是不是真的写进去了

### Q7：编译报奇怪的链接错误（undefined reference to xxx）

- 通常是 `config.h` 漏开了一个 `*_EN` 宏，导致某 `.c` 文件被条件编译排除了
- 或者 `func.c` 的 `switch (func_cb.sta)` 里的某个 `case` 被 `#if FUNC_XXX_EN` 关掉了

### Q8：我想加一个新功能（比如红外遥控），怎么入手？

1. 在 `config.h` 加 `#define IRRX_HW_EN 1`
2. 在 `xcfg.xm` 加红外相关 `config(...)` 项（IRRX 输入引脚选择等）
3. 参考 [app/platform/functions/func.c:312-315](../app/platform/functions/func.c#L312-L315) 的 `case KU_IR_POWER:` 模式，添加你自己的 IR 消息处理
4. 在 `message/msg_bt.c`（或对应 mode）里处理红外按键事件
